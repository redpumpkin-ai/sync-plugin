# sync-projects rules

Read this before step 3 (building the diff table) and again before writing anything. Paths in this file are relative to the skill folder, not to references/.

- **Comments:** read the existing thread first. An equivalent `[PLAN]` or `[UPDATE]` already there → skip, do not duplicate. Comments cannot be edited or deleted, so each is shown in the table before posting. Tags, templates and language follow `../_shared/conventions.md` (`_shared/conventions.md` in a ZIP upload).
- **Status:** not part of this skill. `change_ticket_status` only for BACKLOG, TODO or CANCELED, and only when the user asks. GitHub moves the rest.
- **Project update post:** not posted here. If the user wants one, draft it with the proposed health as a suggestion and post only after an explicit yes. A post cannot be undone; after an unclear response, check the feed before retrying.
- **Lint before writing:** no raw client data (aggregates only); no AI tool or model names if the repo forbids them; no secrets, internal URLs or repo links the user marked as not shareable.
